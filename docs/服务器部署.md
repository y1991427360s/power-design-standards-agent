# gb.sen666.com 部署记录

2026-10-02 已部署到 9 号服务器。访问 https://gb.sen666.com ，在网页输入访问密码，无需用户名。密码说明保存在用户本机 Documents 的独立文本中，未提交仓库。

- 运行：`power-standards.service`（systemd 开机自启、故障重启）
- 源码：`/opt/power-design-standards-agent`
- 资料与聊天：`/var/lib/power-standards`（独立服务用户，目录权限 0700）
- 后端：`127.0.0.1:8030`
- HTTPS：nginx `127.0.0.1:9530`，公网 443 按域名 SNI 分流
- 站点：`/etc/nginx/sites-available/gb.sen666.com`
- 登录哈希：项目 `.env` 的 `LOGIN_PASSWORD_HASH`（PBKDF2）；`SESSION_SECRET` 签名 12 小时的 HttpOnly/SameSite/Secure 会话 Cookie，所有资料与聊天 API 受保护；nginx 对登录限速
- Cloudflare：DNS-only A 记录，源站提供 Let's Encrypt HTTPS；未改变区域 SSL 设置
- 证书：Certbot 自动续期，续期后校验并平滑重载 nginx
- 模型：外部 API 默认关闭，当前仅提供虚构 DEMO

修改模型配置：管理员在服务器项目 `.env` 配置，然后 `sudo systemctl restart power-standards`。更换 Embedding 后重新解析所有文档。所有访问者使用同一个工作区；此登录保护不提供多人数据隔离。

备份：停服或使用 SQLite 在线备份，备份 `/var/lib/power-standards`，以及服务器 `.env`、nginx 配置和登录哈希。凭据和规范资料不得提交到公开仓库。

代码升级：先备份，传输经过测试的源码（保留 `.env` 和数据目录），更新虚拟环境依赖后重启本服务。Nginx 变更必须先 `nginx -t`，再 reload。初次部署配置脚本会拒绝覆盖已有 `.env` 或站点，不可当作无条件重复更新脚本运行。

验证：本地 15 项测试通过，覆盖单密码登录、错误密码、会话签名与退出。公网 HTTPS 未登录跳转到登录页，受保护 API 返回 401；登录后的首页、规范列表、条号/页码/引用、原文件访问、无依据回答和跨站阻止均已验证。
